## Proposed vector-space workflow

1. **Ingest without duplicating originals.** Treat `E:\Envato Stocks`, the project `broll-assets`, and future folders as configurable, read-only media roots. Give each unique clip a stable ID. Probe duration, dimensions, rotation and codec. Record source/Envato URL, license information, subject, action, visible people and setting, Indian-context suitability, medical/context restrictions, usable time ranges, and approval state. Group exact or visually near-duplicate copies.
2. **Sample several useful moments per video.** A single whole-video vector can miss a short action inside a clip. Extract roughly **4–8 representative frames per clip** initially, retaining each frame's timestamp. Use shot boundaries or evenly spaced times as appropriate; refine on a pilot. Do not assume every camera-named file depicts its folder title. Make small previews/contact sheets for human labeling.
3. **Embed locally.** A compatible image–text encoder maps each frame and each spoken query phrase into a shared high-dimensional space. A candidate pilot model is [Google SigLIP 2 Base](https://huggingface.co/google/siglip2-base-patch16-224), which supports image–text retrieval and has multilingual training. Test Hindi phrases and a concise English rendering on actual samples. Its current repository is **1.54 GB**, including a **1.5 GB** weights file, and lists an Apache-2.0 license. This is a candidate, not an installed or quality-validated model.
4. **Search locally.** Combine visual-vector nearest neighbors with SQLite keyword/BM25 search over reviewed captions and bilingual topic aliases. A small exact vector search (array or FAISS Flat) is sufficient to benchmark 1,500–4,000 clips; a separate vector database server is not required at this scale. Filter unavailable, unapproved, unlicensed, technically unusable, or factually misleading candidates. Rerank the small set for action, topic, culture/setting, crop, timing, visual diversity and reuse. Send only about **6–10 candidate IDs and short descriptions per speech beat** to Codex. The gallery itself stays local and does not enter every prompt.
5. **Select video or image.** Use a video only if it passes hard constraints and an editorial fit gate. The proposed target is **at least 80% estimated fit to the exact spoken beat**. Raw cosine similarity of `0.80` is **not** an 80% match probability; first label acceptable/unacceptable clip–speech pairs and calibrate the combined score. If no candidate passes, use the exact supplied product/reference photo where required or generate a relevant still. Record candidate score, chosen asset ID, in/out range, and fallback reason in the manifest.
6. **Prefer fresh footage among equally good matches.** Log clips actually used in completed renders, by stable ID, near-duplicate group, output video, topic, and date. Strongly discourage repeating a clip within the same reel, modestly discourage recent reuse on the same topic, and apply a small long-term penalty. For three equally relevant clips, two unused clips should normally beat one already used. Relevance and factual accuracy take priority, so a previously used exact match can still win. A fresh but irrelevant clip should never displace an image fallback.
7. **Optional 2D map for people.** Project the high-dimensional vectors with UMAP or a similar tool to display clusters, the current spoken query, duplicates and gaps. Use the original high-dimensional score for actual selection; the 2D plot distorts distances. This map is a review aid, not the algorithm's acceptance test.

**Example:** spoken phrase “doctor measuring blood pressure” → local search returns footage of an Indian clinician using a cuff, a generic consultation, and an anatomy animation → exact action and setting checks rank the cuff clip highest → if it meets the calibrated threshold, use its relevant seconds; otherwise use a still. A generic doctor shot is not automatically an adequate match.
